# BugHunter — система учёта и отслеживания дефектов

## 1. Назначение проекта

**BugHunter** — лёгкое веб-приложение класса Bug Tracking System для регистрации, классификации, распределения и контроля жизненного цикла дефектов программного обеспечения в рамках проектов разработки. Система обеспечивает прозрачное взаимодействие между тестировщиками, разработчиками и администраторами с сохранением истории изменений и обсуждений по каждой задаче.

---

## 2. Требования к окружению

Для развёртывания и корректной работы приложения необходимы следующие компоненты:

* **PHP:** версия `8.0` или выше
* **Расширения PHP:**
  * `pdo_sqlite` (для работы с базой данных SQLite через PDO)
  * `mbstring` (для корректной валидации длины многобайтовых строк UTF-8)
  * `session` (для управления пользовательскими сессиями и CSRF-токенами)
* **СУБД:** SQLite 3 (файл базы данных размещается локально, установка отдельного сервера БД не требуется)
* **Веб-сервер:** встроенный сервер PHP (`php -S`), Apache, Nginx или локальные сборки (OpenServer, XAMPP, Laragon) с корневой директорией, настроенной на папку `public/`

---

## 3. Инструкция запуска

1. **Клонируйте или распакуйте проект** в рабочую директорию:
   ```bash
   cd /path/to/bughunter
   ```

2. **Проверьте наличие директории и файла базы данных:**
   Убедитесь, что каталог `database/` существует и доступен на запись для веб-сервера, а файл `database/bughunter.db` находится на месте. При первом подключении приложение автоматически проверит и дополнит недостающие столбцы в таблице `Bugs`.

3. **Запустите встроенный веб-сервер PHP**, указав в качестве корневой директории (`-t`) папку `public`:
   ```bash
   php -S localhost:8000 -t public
   ```
   > **Важно:** Запуск сервера из корневого каталога проекта без флага `-t public` приведёт к ошибке `404 Not Found` при перенаправлениях между страницами.

4. **Откройте приложение в браузере:**
   Перейдите по адресу:
   ```text
   http://localhost:8000/
   ```
   Вы будете автоматически перенаправлены на страницу авторизации (`login.php`).

## 5. Описание возможностей

* **Аутентификация и регистрация:**
  * Регистрация новых пользователей с валидацией email и минимальной длиной пароля (от 8 символов).
  * Безопасное хранение паролей с использованием алгоритма `password_hash()` и проверка через `password_verify()`.
* **Ролевая модель и разграничение прав доступа (RBAC / IDOR-защита):**
  * Поддержка ролей: `Администратор`, `Разработчик`, `Тестировщик`.
  * Редактировать и удалять проект может только его владелец или `Администратор`.
  * Редактировать и удалять дефект может автор (репортёр), назначенный исполнитель, владелец проекта или `Администратор`.
* **Управление проектами:**
  * Создание проектов с уникальным символьным кодом (например, `BH`, `WEB`) и названием, просмотр статистики по количеству дефектов в каждом проекте.
* **Полный жизненный цикл дефектов:**
  * Регистрация багов с указанием проекта, заголовка, подробного описания (`description`), шагов воспроизведения (`steps`), ожидаемого (`expected_result`) и фактического (`actual_result`) результатов.
  * Управление статусами (`Новый`, `В работе`, `На проверке`, `Закрыт`) и приоритетами (`Низкий`, `Средний`, `Высокий`, `Критический`), назначение ответственного исполнителя.
* **Комментарии и аудит изменений:**
  * Добавление комментариев в карточке дефекта с фиксацией автора и времени публикации.
  * Автоматическое журналирование всех изменений полей дефекта в таблицу `BugHistory` (кто изменил, какое поле, старое и новое значение).
* **Информационная безопасность:**
  * Защита всех форм от межсайтовой подделки запросов (CSRF-токены с проверкой через `hash_equals`).
  * Защита от SQL-инъекций с помощью подготовленных выражений PDO (`prepare` / `execute`).
  * Защита от XSS-атак за счёт экранирования пользовательского вывода через `htmlspecialchars()`.
